# FUTURE_ML_Task1 — Sales & Demand Forecasting for Businesses

**Future Interns — Machine Learning Internship | Task 1**

An end-to-end sales forecasting project that cleans historical business data, performs time-series analysis, engineers calendar/lag/rolling features, compares forecasting approaches, evaluates prediction error, produces a 30-day forecast, and converts the results into business-ready insights.

> **Dataset note:** No company dataset was included in the task image provided for this project. Therefore, this repository contains a clearly labelled synthetic demonstration dataset generated by `src/forecast_sales.py`. Replace it with the internship/company dataset when one is provided.

## 🔎 Project workflow

### 1. Data preparation

The pipeline parses dates, sorts records chronologically, checks the required columns, removes rows with missing date/sales values, and aggregates sales to daily revenue for forecasting.

### 2. Time-series feature engineering

The model uses:

- Day of week, month and day of year
- 1, 7, 14 and 28-day lag values
- 7 and 28-day rolling averages

All lag/rolling features are shifted so that future sales are not used to build the predictor for the same date.

### 3. Forecasting models

Three approaches are compared:

1. **7-day seasonal naive baseline** — uses the value from the same weekday one week earlier.
2. **Linear Regression** — a transparent regression model using the engineered time-series features.
3. **Random Forest Regressor** — a non-linear ensemble model for comparison.

### 4. Evaluation

The final 30 historical days are held out chronologically. The test forecast is generated recursively, so predictions are produced sequentially rather than using future actual sales as inputs.

Metrics:

- **MAE:** average absolute forecast error
- **RMSE:** penalizes larger errors more strongly
- **MAPE:** percentage-based forecast error

### 5. Forecast generation

The model with the lowest chronological holdout RMSE is refit on the full historical dataset and used to generate the next 30 days of sales forecasts.

## 📊 Demonstration results

On the included synthetic dataset, the chronological 30-day holdout comparison is:

| Model | MAE | RMSE | MAPE |
|---|---:|---:|---:|
| Linear Regression | 13,662.41 | 16,619.16 | 9.62% |
| 7-day Seasonal Naive | 14,787.44 | 18,014.29 | 11.09% |
| Random Forest | 16,744.07 | 20,104.98 | 12.58% |

The lowest-RMSE model is used for the demonstration forecast. These metrics describe the included synthetic dataset only and should be recalculated when real internship data is supplied.

## 💼 Business interpretation

The generated report includes:

- Expected revenue for the next 30 days
- Average expected daily revenue
- Comparison with the previous 30-day average
- Highest-revenue category
- Highest-revenue region

These outputs can support inventory planning, demand planning, staffing, budgeting, and marketing decisions. They should be treated as planning signals rather than guaranteed future revenue.

## 🧠 Why the logic is simple and practical

The project follows the way a person would normally approach the business question:

1. **Look at the past:** How much was sold each day?
2. **Find useful patterns:** Does the day of the week matter? What happened yesterday, last week and over the last month?
3. **Make a fair test:** Hide the last 30 days and pretend we do not know them yet.
4. **Try a couple of models:** Compare a simple regression with a tree-based model and a last-week benchmark.
5. **Measure the mistakes:** Use MAE, RMSE and MAPE instead of assuming the model is correct.
6. **Forecast the future:** Retrain using all available history and predict the next 30 days.
7. **Explain the result:** Convert the forecast into charts and simple business observations.

This makes the project easier to explain in an internship interview because every modelling decision has a clear business reason.
